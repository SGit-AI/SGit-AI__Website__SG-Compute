⚠ The domain decision

This will be the question this site is asked most often, so it is stated here and repeated in the footer of every page rather than left to be discovered.

documentation

sg-compute.sgit.ai

This site. Static pages on GitHub Pages. It documents and audits the platform; it runs none of it. Nothing here is an endpoint.

a website
running infrastructure

sg-compute.sgraph.ai

A live Route 53 zone, serving per-node DNS as <stack-name>.sg-compute.<zone>. Referenced 128 times in the platform's code and tests, including in code defaults and test assertions.

a DNS zone with real hosts under it

Same label, different TLD. The two options were:

  1. Claim the distinction explicitly — sgit.ai is documentation, sgraph.ai is running infrastructure — and say so on the front page and here.
  2. Move the node DNS to sgit.ai as well, which touches 128 references, every test assertion that names the zone, and every running node.

The decision is option 1, on cost. It is a stated decision rather than a convention that happened, and it is published as Q7 with the case for revisiting it: the argument against it is not technical, it is that a support question arriving every week forever eventually costs more than a migration.

One consequence worth naming: because the zone name is the subject of a published decision, it is the single deliberate exception in this site's leak tripwire, which otherwise bans every live hostname from the tree. Per-node FQDNs under that zone stay banned.
