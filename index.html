Ephemeral compute · sixteen workload specs · agent infrastructure

A compute platform named
after one of its sixteen specs

SG/Compute launches an isolated environment, runs the work, and terminates it. Sixteen ready-to-launch specs — browsers, vaults, container runtimes, model inference, observability — each a typed manifest away from a running node. The repository is still named after one of them, and the number that settles it is this: 71.5% of the new codebase is not browser code.

We should start with a bug we found in its CI

The platform has a guard whose whole job is to stop the new code importing from the legacy package it is being extracted from. It has been passing since the day it was written. It has never once matched anything.

# tests/ci/test_no_legacy_imports.py
r'from\s+sgraph_ai_service_playwright[^_]|import\s+sgraph_ai_service_playwright[^_]'

# [^_] requires a NON-underscore after the stem. The real package is:
sgraph_ai_service_playwright__cli        # two underscores

# run both patterns over the tree:
GUARD regex   : 0 files    -> test PASSES (vacuously)
REAL imports  : 69 files, 228 import lines
FIXED regex   : 69 files   -> test FAILS, as intended

Deleting four characters turns it red. And the dependency runs both ways — the legacy package imports the new one 72 times — so the cycle the guard's own docstring says was broken is not broken.

A platform site that leads with a bug it found in its own CI is trusted differently from one that leads with a feature list. That is the whole editorial policy of this site, stated once at the top. The guard, in full · it is fix F1 of seven, and it takes four characters.

Two ephemeral layers, and conflating them is the common misreading

Almost everyone reading this platform for the first time collapses these into one thing. They are different, they have different lifetimes, and separating them is the single most useful thing this site can do on page one.

Layer 1 · per HTTP request

An ephemeral browser

Every call launches a fresh Playwright subprocess and a fresh Chromium, runs the declared step list, and tears both down in try/finally before returning. There is zero cross-request state, and a CI guard fails the build if any raw browser.new_context( appears outside the one sanctioned factory.

lifetime: one request · milliseconds to seconds
Layer 2 · per node

An ephemeral EC2 instance

A per-node API key minted and written to SSM before launch, composed user-data, EC2 tags as the registry, a two-phase health poll — then systemd-run --on-active paired with InstanceInitiatedShutdownBehavior=terminate. Halt means terminate, not stop. Default one hour, everywhere.

lifetime: one hour by default · 0.1h to unbounded

Three axioms, rescued from a file that is 42 versions stale

They are named in capabilities.json, which is frozen at v0.1.29 while the code is at v0.2.71 — and which the repository's own documentation tells you not to read. The axioms are good, and unlike the file that names them, they are actually implemented.

axiom 1

Statelessness

Fresh browser process, fresh context, fresh page, per request — torn down in try/finally whatever happens. Cookies apply to the per-request context and are discarded with it.

How it is enforced →
axiom 2

Least privilege by declaration

The JavaScript allowlist is deny by default, exact match. An agent cannot evaluate anything until an operator populates the list. Nothing is permitted by omission.

The isolation boundaries →
axiom 3

Self-description

GET /health/capabilities is built at runtime by a detector that works out its own deployment target — laptop, CI, container, Lambda. The service tells you what it can do, live.

And here is what is not built

The most quotable ideas in this platform's corpus are the ones with no code behind them. That is worth stating on the front page rather than three clicks in, because the repository's own governing rule already says it: “briefs are aspirations, not facts.”

not built

Warm pools

Central to the serverless pitch and specified in a 1,729-word brief with worked economics. Zero implementation. Grep finds one idle-teardown threshold and nothing else.

The ledger →
not built

Multi-node stacks

A Stack is meant to be 2+ coordinated Nodes — the taxonomy's whole point. The routes return a list, the CLI is unwired, and thirteen help strings use “stack” for a single instance.

The ledger →
not built

S3 and vault artefact sinks

Four sinks declared, two implemented. No S3, no presigned URLs, no vault writes — today it is base64 inline with a 20 MB cap, or a local file.

The ledger →
broken

The AMI bake pipeline

A genuinely good two-phase bake-and-verify workflow that invokes a binary called sg-play sixteen times. sg-play is defined nowhere. The whole workflow is dead.

One thing to state before you discover it

sg-compute.sgit.ai is this site: documentation. sg-compute.sgraph.ai is a live Route 53 zone serving per-node DNS as <stack-name>.sg-compute.<zone>, referenced 128 times in the platform's code and tests. Same label, different TLD.

The alternative was moving 128 references and every running node. We did not; we are claiming the distinction instead, and saying so here rather than letting you find it in a support thread. The decision, and where it could still bite →
